# 📌 Code Convention

본 프로젝트는 가독성, 유지보수성, 협업 효율성을 높이기 위해\
아래와 같은 코드 컨벤션을 따릅니다.

------------------------------------------------------------------------

## 1. Branch Strategy

    main
     ├─ feature/기능명
     ├─ fix/버그명

### 규칙

-   모든 브랜치는 **main 기준으로 생성**
-   기능 단위로 브랜치 분리
-   작업 완료 후 **Pull Request 생성 후 main 병합**

------------------------------------------------------------------------

## 2. Commit Message Convention

### 형식

    타입: 작업 내용 요약

### 타입 종류

| 타입      | 설명                      |
|-----------|---------------------------|
| feat      | 새로운 기능 추가           |
| fix       | 버그 수정                 |
| refactor  | 코드 리팩토링             |
| chore     | 설정, 빌드, 패키지 수정    |
| docs      | 문서 수정                 |
| test      | 테스트 코드               |


### 예시

    feat: 로그인 API 구현
    fix: 토큰 만료 예외 처리 수정
    refactor: 서비스 레이어 구조 개선
    chore: gradle 설정 추가
    docs: README 업데이트

------------------------------------------------------------------------

## 3. Pull Request Convention

### 제목

    [타입] 작업 내용 요약

### 예시

    [feat] 친구 신청 기능 구현

------------------------------------------------------------------------

## 4. Code Style

### 4-1. 네이밍 규칙

| 대상   | 규칙              |
|--------|-------------------|
| 클래스 | PascalCase        |
| 메서드 | camelCase         |
| 변수   | camelCase         |
| 상수   | UPPER_SNAKE_CASE  |
| 패키지 | 소문자            |

------------------------------------------------------------------------

### 4-2. 메서드 작성 규칙

-   하나의 메서드는 **하나의 책임만**
-   길어지면 기능 단위로 분리
-   의미 있는 메서드명 사용

------------------------------------------------------------------------

## 5. API 설계 규칙

### RESTful 원칙

| Method | URL                    | 설명                    |
|--------|------------------------|-------------------------|
| GET    | /api/friends           | 친구 목록 조회          |
| GET    | /api/friends/request   | 받은 친구 신청 목록 조회 |
------------------------------------------------------------------------

## 6. Exception Handling

-   공통 예외 처리 사용
-   비즈니스 예외는 커스텀 Exception 정의
------------------------------------------------------------------------

## 7. Logging Convention

-   System.out.println 사용 금지
-   Logger 사용
------------------------------------------------------------------------

## 8. Test Convention

-   기능 단위 테스트 작성
-   테스트 메서드명은 행위 중심

------------------------------------------------------------------------

## 9. 기타 규칙

-   하드코딩 금지 → 상수화
-   중복 코드 최소화
-   의미 없는 주석 작성 금지

------------------------------------------------------------------------

## ✅ 목표

> 본 컨벤션을 통해\
> **가독성 높은 코드 + 협업 가능한 구조**를 유지합니다.
